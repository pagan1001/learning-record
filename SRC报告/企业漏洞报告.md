# MySQL数据库基础

## MySQL Base
><big>**系统库释意**</big><br><br>
<mark>***information_schema***</mark> 库：是信息数据库，其中保存着关于MySQL服务器所维护的所有其他数据库的信息，比如数据库名，数据库表，表字段的数据类型与访问权限等，Web渗透过程中用途很大。<br><br>
<mark>***SCHEMATA***</mark> 表：提供了当前MySQL实例中所有的数据库信息。 <mark>***show databases***</mark> 结果取值此表。<br><br>
<mark>***TABLES***</mark> 表：提供了关于数据中表的信息<br><br>
<mark>***COLUMNS***</mark> 表：提供了表中的列信息，详细描述了某张表的所有列以及每个列的信息。<br><br><br>
<mark>***mysql***</mark> 库：MySQL的核心数据库，主要负责存储数据库的用户、权限设置、关键字符mysql自己需要使用的控制和管理信息。<br><br>
<mark>***performance_schema***</mark> 库：内存数据库，数据放在内存中直接操作的数据库，相对于磁盘，内存的数据读写速度要高出几个数量级，将数据保存在内容中相比从磁盘上访问能够极大地提高应用的性能。<br><br>
<mark>***sys***</mark> 库：通过这个数据库，可以查询谁使用了最多的资源，基于IP或用户，哪张表被访问最多等等信息。

## 基础语法 

### 注释
```mysql
--(空格)内容     //第一种注释
#内容           //第二种注释
```

### 创建用户并授权
>username：用户名 <br>
host：可以连接的的主机 'localhost'表示只能本机连接，'%'表示任何一台机器都可以连接，也可以通过ip地址，规定某台远程主机可以连接<br>
password：连接密码。''表示不需要密码
```sql
// 5.x版本 没有用户自动创建并赋权
grant all on *.* to 'username'@'host' identified by 'password';

// 8.x版本 先创建用户，再赋权
create user 'username'@'host' identified by 'password' with_native_password;

GRANT ALL PRIVILEGES ON . TO 'username'@'host'; 
```

### select
```sql
select now();                   //查看当前时区时间
select database();              //查看当前数据库
select version();               //查看数据库版本
select user();                  //查看当前登录用户
select @@datadir;               //查看数据路径
select @@basedir;               //查看MySQL安装路径
select @@version_compile_os;    //查看MySQL安装的系统
```

```sql
// select查询关键字，*表示查询所有
```

### information_schema库
***验证 show databases 结果来源于 SCHEMAT 表***
```sql
// 查询SCHEMATA表发现有column名为SCHEMA_NAME
select * from information_schema.SCHEMATA;

// 查看 show databases 结果发现与SCHEMA_NAME数据一致
// SQL注入时可以从SCHEMATA表中拿库名
select SCHEMA_NAME from information_schema.SCHEMATA;
```

***从 information_schema.tables 表查表名***
```sql
//  TABLE_NAME 字段为所需表名
select * from information_schema.tables where table_schema = 'test';
```

***从 information_schema.columns 表查列名***
```sql
//  COLUMN_NAME 字段为所需列名
select * from information_schema.columns where table_schema = 'test';
```

### where
```sql
// 指定查找root用户
select user,host from mysql.user where user = 'root';

// 指定查找host为%
select user,host from mysql.user where host = '%';
```
### 查询
```sql
// 与查询
select * from test.t1 where name = '张三' and id = 1;

// 或查询
select * from test.t1 where name = '张三' or id = 1;

// 联合查询
select * from test.t1 where name = '张三' union select user,host from mysql.user;
```

### 创建
#### 创建库
<big>*CHARSET*</big>：CHARSET表示数据编码方式，在MySQL中可以使用命令 <mark>***show variables like 'character_set_%;***</mark> 查看系统默认编码集。<br>
在我们的业务场景中因为经常会涉及到中文，常用的编码方式就是utf-8，但是在MySQL中的utf8编码其实并不是我们平时使用的utf-8编码，正确的对应编码是 <mark>***utf8mb4***</mark> ，在MySQL中utf8编码最多只能支持3 bytes长度的字符编码，对于一些需要占用4 bytes的字符使用utf8编码方式就不支持了，需要使用 <mark>***utf8mb4***</mark> 才行，这是MySQL的一个<mark>***遗留问题***</mark> 。<br>
我们在使用MySQL时，如果使用的是5.7及以前的版本，需要我们 <mark>***手动***</mark> 将编码方式配置为utf8mb4，如果使用的是版本8+则默认就是该编码了，不需要我们再修改了。修改MySQL默认字符集，可以在 <mark>***/etc/my.cnf***</mark> 配置文件中修改对应的编码即可，注意不同的版本修改方式可能有些不太一样。<br>

![alt text](photos/image2.png)

<big>*COLLATE*</big>：COLLATE属性用于指定列的排序和比较方式，我们在使用 <mark>***ORDER BY、DISTINCT、GROUP BY***</mark> 等命令时都会涉及到该属性。另外我们在对表建索引时，如果索引列是字符类型，那么COLLATE属性也会影响到索引的创建。<br>
COLLATE通常是和字符编码CHARSET相关的，每种CHARSET都对应了多种它所支持的COLLATE，并且会指定一个默认COLLATE。比如utf8mb4编码的默认COLLATE为utf8mb4_general_ci，对于中文场景来说，其实 <mark>***utf8mb4_unicode_ci***</mark> 和 <mark>***utf8mb4_general_ci***</mark> 没有什么区别。我们可以使用命令show collation;查看MySQL所支持的COLLATE。<br>
我们会发现，很多COLLATE里面都带有_ci后缀，这是 <mark>***Case Insensitive***</mark> 的缩写，表示大小写无关。对应的_cs后缀表示大小写敏感。<br>
需要注意的是，在MySQL 8+版本中，默认的CHARSET直接改成了utf8mb4，对应的默认COLLATE也改成了 <mark>***utf8mb4_0900_ai_ci***</mark> ，这是unicode的一个细分，就相当于 <mark>***utf8mb4_unicode_ci***</mark>。

```sql
// 5.x版本需要手动设置字符集为utf8mb4，8.x版本为默认
create database test charset utf8mb4;
```
